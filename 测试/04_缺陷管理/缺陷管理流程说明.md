# 缺陷管理流程说明

> 平台：禅道（ZenTao）
> 目标：缺陷全生命周期（提交→跟进→修复→验证→关闭）可追踪、可度量、可闭环。

---

## 一、缺陷状态流转

```
 激活(测试提交) ──确认──▶ 已确认(开发受理) ──修复──▶ 已解决(开发)
                                                        │
      ┌──────────── 验证不通过(重新激活) ◀──────────────┘
      ▼
 已关闭(测试验证通过)       已取消(确认非缺陷/放弃)
```

| 状态 | 责任人 | 说明 |
|------|--------|------|
| 激活 | 测试 | 提交缺陷，含复现步骤与佐证 |
| 已确认 | 开发 | 受理并分配 |
| 已解决 | 开发 | 修复完成，注明解决方案与版本 |
| 已关闭 | 测试 | 验证通过，闭环 |
| 重新激活 | 测试 | 验证不通过，回退开发 |

## 二、缺陷提交规范（测试侧）

1. **可复现**：附清晰的复现步骤（前置条件→操作→预期→实际）；
2. **可定位**：附接口/页面路径、请求与响应报文、日志片段；
3. **可分级**：按影响面定严重程度，按业务重要性定优先级；
4. **有佐证**：截图存放于 `02_接口测试/接口缺陷记录模板.md` 约定的 `缺陷截图佐证/` 目录。

## 三、缺陷分级标准

| 级别 | 严重程度 | 判定标准 | 处理时限建议 |
|------|----------|----------|--------------|
| P0 | 致命/严重 | 系统不可用、核心交易流程阻断、资金/数据错误 | 立即修复 |
| P1 | 严重/一般 | 主流程功能异常、数据不一致、越权风险 | 当版本内修复 |
| P2 | 一般/轻微 | 常规功能缺陷、提示不准确 | 尽快修复 |
| P3 | 轻微 | 体验/文案/边界细节 | 择期处理 |

## 四、闭环验证要求

- 每个「已解决」缺陷由**测试独立验证**，验证内容含：
  1. 原始复现路径回归；
  2. 相关功能回归（防止修复引入新缺陷）；
  3. 关联数据校验脚本复核（数据类缺陷）；
  4. 数据库/接口层面佐证（截图或日志）。
- 验证通过 → 关闭并记录关闭时间；验证不通过 → 重新激活，激活次数 +1。

## 五、闭环佐证清单

| 佐证 | 存放位置 |
|------|----------|
| 缺陷台账（全生命周期） | `禅道缺陷台账.csv` |
| 缺陷提交/复现/定位过程 | `02_接口测试/接口缺陷记录模板.md` |
| 缺陷截图 | `02_接口测试/缺陷截图佐证/`（按需建目录） |
| 数据类缺陷佐证 | `03_数据校验与报表测试/数据异常问题台账模板.md` |
| 修复验证报告 | 本目录 `缺陷修复验证报告/`（每个闭环缺陷一份） |

## 六、缺陷统计指标（执行后回填）

| 指标 | 数值 | 口径 |
|------|-----:|------|
| 缺陷累计总数 | | 台账全部记录 |
| 高优先级缺陷数 | | 优先级 P0 / 严重程度 1-2 |
| 已修复缺陷数 | | 状态=已解决 |
| 已闭环缺陷数 | | 状态=已关闭 |
| 闭环率 | | 已关闭/已修复 |
| 平均修复时长 | | (解决时间-创建时间)均值 |
