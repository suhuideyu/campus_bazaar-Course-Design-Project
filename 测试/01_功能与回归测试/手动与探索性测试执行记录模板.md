# 手动与探索性测试执行记录

> 用途：登记手动测试与探索性测试的每次执行情况，作为回归覆盖率统计与缺陷溯源的数据来源。
> 执行方式：按 `220条测试用例.csv` 抽测 + 探索性测试（基于业务风险自由探索）。
> 登记规范：每次执行完成后，将执行结果追加到本文件附表（或导出为独立 CSV）。

---

## 一、执行记录表结构

| 字段 | 说明 |
|------|------|
| 执行ID | 格式 `EXEC-YYYYMMDD-###`，当天流水号 |
| 执行日期 | 实际执行日期 |
| 执行类型 | 手动用例执行 / 探索性测试 |
| 测试轮次 | 所属回归轮次（如 R1/R2/R3） |
| 用例ID范围 | 本轮覆盖的用例ID（如 CB_TC_001~CB_TC_080） |
| 业务模块 | 涉及模块（用户/商品/分类/订单/留言/评价/收藏/管理后台） |
| 执行人 | 测试执行人 |
| 通过数 | 结果=通过 的用例数 |
| 失败数 | 结果=失败 的用例数 |
| 受阻数 | 环境/数据原因无法执行的用例数 |
| 缺陷ID | 本轮新提交的缺陷编号（关联 `04_缺陷管理/禅道缺陷台账.csv`） |
| 备注 | 环境、数据准备、风险说明 |

## 二、探索性测试要点

1. 按业务风险优先级探索：资金流转（订单/价格）> 状态机（商品/订单状态联动）> 越权/安全 > 边界输入。
2. 探索性测试不强制对应具体用例，但发现的每个问题须登记到缺陷台账。
3. 每轮探索性测试完成后，记录探索到的模块、发现、已覆盖的隐性场景。
