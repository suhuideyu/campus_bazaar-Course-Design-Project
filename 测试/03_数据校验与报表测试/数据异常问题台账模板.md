# 数据异常问题台账

> 用途：登记数据一致性校验发现的异常，跟踪处理闭环。
> 数据来源：`MySQL校验脚本/` 执行结果（返回非 0 行的校验项）。
> 登记规范：每次校验发现异常即登记一条；修复或确认可接受的异常标记处理结果。

---

## 一、异常登记表结构

| 字段 | 说明 |
|------|------|
| 异常编号 | `DATA-###` |
| 发现日期 | 校验执行日期 |
| 发现方式 | 校验脚本编号（DB-CK-###） |
| 涉及域 | 用户/订单/交易/库存/商品/评价等 |
| 异常描述 | 返回行数 + 数据摘要 |
| 影响范围 | 影响的表/记录数 |
| 严重程度 | 严重/一般/轻微 |
| 根本原因 | 初判根因 |
| 处理方案 | 修复 SQL / 业务处理 / 确认可接受 |
| 处理状态 | 待处理/处理中/已修复/已确认可接受 |
| 处理人/日期 | 责任人与时间 |

## 二、异常发现与根因分析路径

1. **校验执行** → 返回非 0 行 → 登记异常。
2. **数据取证**：导出异常记录明细，结合接口测试与业务规则确认是否真异常（排除"规则允许"场景）。
3. **根因定位**：
   - 计数不一致（fav_count / view_count）→ 大概率计数缓存/冗余字段未同步；
   - 状态联动不一致 → 大概率事务提交缺失（Service 层未在同一个事务中更新两表）；
   - 外键悬空 → 大概率数据清洗或删除策略问题；
   - 价格不一致 → 大概率并发改价/状态机缺陷。
4. **修复与复核**：修复后重跑对应校验脚本，确认返回 0 行。
