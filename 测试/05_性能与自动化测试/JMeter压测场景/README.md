# JMeter 并发压测场景

> 位置：本目录，5 个 `.jmx` 场景配置文件
> 被测系统：校园二手集市（Spring Boot，localhost:8080）
> 使用方法：JMeter 打开 `.jmx` → 配置线程数/时长 → 运行 → 查看聚合报告

---

## 一、场景清单

| # | 文件 | 场景 | 并发 | 爬坡 | 时长 | 关键接口 |
|---|------|------|-----:|-----:|-----:|----------|
| 1 | `01_登录并发压测.jmx` | 登录接口并发 | 150 | 30s | 5min | POST /api/users/login |
| 2 | `02_首页浏览压测.jmx` | 首页商品列表 | 150 | 30s | 5min | GET /api/items |
| 3 | `03_商品搜索压测.jmx` | 商品搜索 | 100 | 20s | 5min | GET /api/items?keyword= |
| 4 | `04_下单流程压测.jmx` | 下单核心流程 | 80 | 30s | 5min | 登录→商品列表→提交订单 |
| 5 | `05_混合业务压测.jmx` | 混合业务（登录/浏览/详情/搜索/分类/订单） | 150 | 40s | 10min | 多接口混合 |

> 场景 1/2/4/5 的并发配置可覆盖「最高并发 150 用户」的目标区间，
> 场景 4 为下单核心流程（含登录态与参数提取）。

## 二、运行步骤

1. 启动 MySQL 与后端（`cd campus-bazaar-boot && mvn spring-boot:run`）。
2. 打开 JMeter，`File → Open` 选择对应 `.jmx`。
3. 检查 HTTP 请求默认值中的 `localhost:8080` 与你的环境一致。
4. 点击绿色三角运行；结束后查看 **聚合报告**（吞吐量/平均响应时间/错误率/90%分位）。
5. 性能指标登记到 `../性能测试报告.md`。

## 三、场景说明与数据准备

| 场景 | 说明 | 数据前提 |
|------|------|----------|
| 01 登录 | 用种子用户 zhangsan 并发登录 | 用户 zhangsan 存在且未被禁用 |
| 02 首页 | 纯读接口，无状态依赖 | 库中有在售商品即可 |
| 03 搜索 | 纯读接口 | 无特殊要求 |
| 04 下单 | 提取列表首个在售商品 ID 后下单 | **每轮压测前需将有商品恢复在售**（下单会锁定商品）；可准备多个在售商品或用脚本复位商品状态 |
| 05 混合 | 各接口按顺序执行，模拟真实用户路径 | 登录用户有效即可 |

## 四、结果判定口径

| 指标 | 说明 | 判定建议 |
|------|------|----------|
| 吞吐量 (TPS) | 每秒请求数 | 与基线对比，回归不劣化 |
| 平均/90%响应时间 | 接口时延 | 读接口 P90 目标见性能测试报告 |
| 错误率 | 非2xx/业务码非200占比 | 目标 <1% |
| 并发曲线 | 150并发下稳定性 | 无大面积超时/连接拒绝 |

## 五、扩展与注意事项

- 修改线程数：选中 Thread Group → 修改 `线程数(用户)` 与 `Ramp-Up 时间`。
- 场景 4 依赖登录态：JMeter 通过 HTTP Cookie 管理器自动维持 Session Cookie。
- 真实压测建议在独立环境执行，避免本地 IDE/数据库争抢资源导致指标失真。
