# 回归测试效率优化对比报告

> 优化对象：核心流程回归套件（`Pytest接口自动化/`，50 条接口自动化用例）
> 优化手段：数据隔离 + 并行执行 + 智能失败重跑
> 说明：本报告给出**度量方法、优化措施与前后对比记录结构**；回归耗时的实际数值以真实回归运行计时回填。

---

## 一、度量方法

回归执行时长 = 在干净环境（后端 + 初始化数据库）下完整运行回归套件所需时间，计时口径统一：

1. 同一台机器、同一后端实例；
2. 数据库为同一份初始化数据（`campus_bazaar.sql`）；
3. `pytest` 从零开始执行全部 50 条用例至全部结束；
4. 记录总耗时（wall-clock）与失败数。

> 对比时需保证两次运行的**环境、用例集合、数据规模一致**，差异才具备可比性。

## 三、优化措施（框架已落地实现）

| 措施 | 实现 | 收益点 |
|------|------|--------|
| **数据隔离** | 每次运行注册唯一用户名/手机号（`utils/data_factory.py`），订单链路现场创建独立数据 | 消除用例间数据依赖，避免前置清理，可安全并行 |
| **并行执行** | 接入 `pytest-xdist`，`pytest -n auto` | 多进程并行执行用例，耗时近似按核数下降 |
| **失败自动重跑** | 接入 `pytest-rerunfailures`，`--reruns 1` | 屏蔽偶发环境抖动，减少人工介入重跑 |
| **用例排序** | 接入 `pytest-ordering`，核心主流程优先 | 早期暴露高风险问题 |
| **HTML 报告** | 接入 `pytest-html` | 结果沉淀，回归数据可追溯 |
| **配置收敛** | `pytest.ini` 统一 testpaths/addopts | 一条命令完成全量回归 |
