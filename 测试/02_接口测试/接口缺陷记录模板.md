# 接口缺陷记录

> 用途：登记接口测试过程中定位与复现的缺陷，形成缺陷定位过程、复现步骤与佐证材料清单。
> 登记规范：每个缺陷登记一条记录；截图佐证统一存放于本目录 `缺陷截图佐证/` 子目录。
> 关联：缺陷正式编号与全生命周期管理见 `04_缺陷管理/禅道缺陷台账.csv`。

---

## 一、缺陷登记表结构

| 字段 | 说明 |
|------|------|
| 缺陷编号 | 格式 `BUG-API-###`，与禅道台账编号对应 |
| 模块 | 用户/商品/分类/订单/留言/评价/管理后台 |

| 复现步骤 | 触发缺陷的具体步骤 |

| 实际结果 | 系统实际行为 |
| 状态 | 未修复/修复中/已修复/已验证/关闭 |
| 佐证截图 | 截图文件路径（存于 `缺陷截图佐证/`） |
| 提交人/日期 | 记录责任人与时间 |

## 二、缺陷定位方法说明

1. **抓包定位**：使用浏览器 DevTools / Charles / Fiddler 抓取请求与响应，确认是入参问题还是响应问题。
2. **接口日志定位**：查看后端日志（application 控制台/日志文件），定位异常堆栈所在 Service/DAO 层。
3. **数据层定位**：对可疑场景执行关联 SQL 校验，确认是否为数据不一致问题（关联 `03_数据校验与报表测试`）。
4. **代码定位**：对疑似逻辑缺陷，查阅对应 Service 实现类确认业务规则是否与预期一致。
